# 视觉成果与应用交付

以用户参考与指定载体决定风格和范围。完整“纹样焕活”交付让用户先看到单元、连续纹样和应用效果，再提供参数与记录。不要以脚本运行成功、目录数量或一张底纹替代视觉成果。

## 完整成果的关系

1. 原型与提取对照、干净线稿单元、彩色单元：来源选区明确，整理与补绘有说明。
2. 彩色连续纹样与线稿、独立重复块及至少3×3预览：共同引用选定母版，查实际接缝。
3. 海报与包装：沿用户应用参考组织色块、品牌图形、文字和纹样层级，不强制“上标题下满铺”；面向消费者的稿件不默认加入脚本名称、验收状态等说明。
4. 指定文创应用：布包强调纹样尺度、布料、褶皱与整体形状；磁贴展示同一批模块的拆分、组合目标、边界关系与单枚文件，区分自由摆放完整单元和拆块还原图案；紫陶/印章依据实际尺寸、工艺再定稿。平面图、参考照片与新生成产品效果图明确区分。
5. 配套交接：[提示词包](portable-prompts.md)、形态/色彩/寓意证据卡、[定制SOP](service-sop.md)、可编辑源稿、已看图预览及用途说明。

用户指定数量优先；仅做局部修改则按局部范围交付。比赛要求的30+照片、10–15元素卡、3款样机、5份用户测试等，只有实际完成才计入；单个案例不能宣称整队成果达标。

## 图像验收

实际看每张预览：单元可识别、图形无断裂/多余碎片、文字可读不出框、应用层级符合参考、载体与贴图关系合理。生成式样机核对是否偷偷替换了纹样；记录候选偏差。把可编辑路径、栅格预览、AI候选、实物照片分别标清，不将位图封装成SVG叫矢量定稿。

真实刀版、切割容差、磁铁安装、紫陶烧成、食品信息、CMYK及字体设备兼容按实际供应商核对。未核对时交付概念设计或应用候选。

本包 `scripts/run_delivery.py` 从[实际需求配置](delivery-config.md)指定的静态SVG复现数字交付，可变单元、颜色、周期、尺寸和文案；四瓣与真实八角均有示例。它不生成照片级样机。实际生成使用可用图像工具或把[对话入口](chat-handoff.md)及参考交到其他AI。

完整多图流程先用[输出控制](output-control.md)管理素材角色与成果状态。数字工具另导出包装四面展开概念、磁贴模式/拼合记录及`验收记录.json`；自动检查与人工审图分列。审图或外部复现未完成时不得把总状态写成全部通过。

海报主标题默认一个，单元与主题图形形成明确焦点，连续纹样作辅助。内部有交叉线或节点的单元，不能用标志遮住识别特征；品牌图形是否出现按构图决定，提供资产不意味着每项应用都必须使用。
