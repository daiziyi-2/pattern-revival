# 豆包与其他 agent 的交接入口

用户以豆包测试，兼容目标是其他agent。兼容以真实能力和结果验证，不能因为有一个SKILL目录就宣称所有平台能安装、运行Python或导出SVG。

## 选择入口

- 可读取技能目录且具备文件/脚本工具：加载SKILL.md，按本地工具说明运行；只安装到用户指定位置。复制整个技能目录，保留assets、scripts和references的相对结构。
- 能接收文字与图片：复制`assets/handoff/通用对话入口.txt`，上传本次真实单元/连续纹样与产品或版式参照。支持文件附件时也可附Skill与相关参考；不可读文件时直接粘贴必要正文。
- 只要复现已选成稿：复制该成果的提示词TXT，按编号上传同一参考包中的PNG/JPG。图片数受限时，结构母版与目标成稿优先，产品效果再加载体图；品牌标志不能被文字猜测替代。

接收附件、生成图片、运行脚本和导出文件是不同能力。另一个平台不能运行本包工具时，可用提示词完成其具备的生图部分，再将候选交回设计工具处理精确路径与中文。没有实际输出图片时标为提示词交付，不称完整视觉交付。

完整成果目录已经把`通用对话入口.txt`复制到根目录；只使用该交付目录时直接复制根目录文件即可，不必另找技能安装位置。

## 用户可以直接执行的测试

在豆包或目标agent中开一个新对话，先粘贴通用入口，再上传要测试的图片，使用普通需求：

> 用这个单元做连续纹样和一张竖版海报，保留原来的结构。采用我给的色板，给我实际图片，并附能在其他AI继续生图的完整提示词。海报主标题只出现一次。

需要单独测局部编辑时，上传确定连续稿：

> 只把这张彩色纹样变成白底黑线，保持形状、数量、位置和裁切。请给实际结果和对应提示词，不重新设计。

不要告诉测试agent本次预期布局，不给它旧案例代答。人工记录：实际接收了哪些图、是否保持单元、是否完成指定成果、提示词是否实填、文案是否准确、是否偷偷借用别的案例、工具不支持时是否如实说明。

另测参考分类与拆拼：明确告诉目标agent“实景图是载体参考，其他是已定纹样；用同一纹样做可拆拼磁贴，展示拼回图案、拆分与单枚”。检查它是否把参考照片当成自己的产出、是否改变包型或借入旧花纹、是否仅摆四张图形卡而未说明拼回关系。按[输出控制](output-control.md)记录每项实际状态。

本包可运行的跨案例测试证明脚本处理另一单元、颜色和尺寸；解压测试证明文件迁移。二者均不能替代豆包或其他agent的实际对话测试，也不证明任意照片自动提取成功。新版交接入口按阶段连续执行，无需每阶段确认；失败项具体标明，不宣称全部通过。
